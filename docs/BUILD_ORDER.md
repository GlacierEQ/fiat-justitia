# Tower Completion Build Order

## P0 — Truth convergence

- `registry/tower.yml` is the canonical root and its declared fragments are the technology records.
- All advertised technologies are registered.
- README, runtime registry, sidecar, mesh maps, maturity data, build commands,
  interface graph, per-floor manifests, and integrity data derive from it.
- Counts are computed.
- Every advanced exhibit has an evidence state and proof class.

## P1 — Executable Tower

- Each floor declares a pinned reference toolchain and argv-safe build/test commands.
- CI runs portable floors and reports hardware, service, platform, and toolchain blockers.
- Integrity verification hashes every governed source file.
- The five weakest original advanced exhibits are upgraded.
- ONNX, MLIR, FlatBuffers, Cap'n Proto, SystemVerilog, VHDL, Chisel, Coq, and Agda are admitted.

## P2 — System power

- The flagship mission pipeline traverses TypeScript, Python, Rust, Go, SQL,
  WebAssembly, Lean 4, and Protobuf.
- Build and proof reports are hash-bound.
- The Tower-to-Megamind Protobuf adapter exposes technology selection.
- Every technology maps to Megamind agents and pistons.
- Tower exports are the only technology-diversification authority.

## Definition of done

The machine checks in `tests/` encode the completion contract. The release
receipt is valid only when registry validation and integrity verification pass.
